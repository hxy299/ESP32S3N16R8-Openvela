# docs/protocol/ — 蓝牙通信协议契约

> **这是 ESP32-S3（下位，Peripheral）与 Radxa A7Z（上位，Central）之间的接口契约。**
> 双方各自实现，以本文档为准。协议变更必须先改本文档。

## 1. 角色划分

| 端 | 设备 | GATT 角色 | 说明 |
| --- | --- | --- | --- |
| 上位 | Radxa A7Z（已适配 openvela） | **GATT Client / Central** | 主动扫描、连接、下发命令 |
| 下位 | ESP32-S3-N16R8（本项目） | **GATT Server / Peripheral** | 广播、接受连接、执行并回报 |

> ⚠️ **待确认**：A7Z 侧的蓝牙能力。A7Z 已完成的 openvela 适配是否包含可用的
> BLE host 协议栈？它作为 Central 是否已验证过？这决定本项目能否成立。
> 见 [`../stages/stage-00-project-init.md`](../stages/stage-00-project-init.md)。

## 2. 设备命名与广播

| 项 | 建议值 | 说明 |
| --- | --- | --- |
| 广播名 | `BTSH-LIGHT-<后4位MAC>` | 便于 A7Z 识别与多设备区分 |
| 广播内容 | 包含主服务 UUID（128 位） | 让 A7Z 免连接即可过滤 |
| 连接参数 | 建议 interval 30–50 ms | 兼顾响应与功耗 |

## 3. 服务与特征（草案，待确认后冻结）

采用自定义 128 位 UUID。**以下 UUID 为初稿，冻结前不要写进固件。**

| 用途 | UUID（草案） | 属性 |
| --- | --- | --- |
| 灯控服务 | `0000a001-0000-1000-8000-00805f9b34fb` | Primary Service |
| ├ 命令特征 | `0000a002-0000-1000-8000-00805f9b34fb` | Write / Write Without Response |
| ├ 状态特征 | `0000a003-0000-1000-8000-00805f9b34fb` | Read / Notify |
| ├ 设备信息 | `0000a004-0000-1000-8000-00805f9b34fb` | Read（固件版本、通道数） |
| └ 心跳特征 | `0000a005-0000-1000-8000-00805f9b34fb` | Notify |

> ⚠️ 采用蓝牙基址 `0000xxxx-0000-1000-8000-00805f9b34fb` 是偷懒写法，
> 正式版建议用随机生成的 128 位 UUID 以避免撞车。**待用户/A7Z 侧确认。**

## 4. 报文格式

### 4.1 命令（A7Z → ESP32-S3，写命令特征）

```
字节:  0        1        2..N
     ┌────────┬────────┬──────────────┐
     │ OPCODE │ LEN    │ PAYLOAD      │
     └────────┴────────┴──────────────┘
```

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| OPCODE | 1 B | 操作码 |
| LEN | 1 B | PAYLOAD 字节数（0–16） |
| PAYLOAD | LEN B | 参数 |

### 4.2 操作码（草案）

| OPCODE | 名称 | PAYLOAD | 说明 |
| --- | --- | --- | --- |
| `0x01` | `SET_LIGHT` | `ch(1B), state(1B)` | `state`: 0=关, 1=开 |
| `0x02` | `GET_STATE` | `ch(1B)` | 查询指定通道 |
| `0x03` | `SET_ALL` | `state(1B)` | 全部通道 |
| `0x81` | `ACK` | `opcode(1B), result(1B)` | 执行结果 |
| `0x82` | `STATE_REPORT` | `ch(1B), state(1B), src(1B)` | 状态上报（Notify） |
| `0x83` | `HEARTBEAT` | `uptime(4B, 小端)` | 心跳（Notify） |

### 4.3 结果码

| 码 | 含义 |
| --- | --- |
| `0x00` | 成功 |
| `0x01` | 未知操作码 |
| `0x02` | 参数错误 |
| `0x03` | 通道号越界 |
| `0x04` | 硬件执行失败 |

## 5. 交互时序（第一阶段：远程点灯）

```
A7Z                                  ESP32-S3
 │                                        │
 │  ① 扫描，按名称/服务 UUID 过滤           │  ← 广播中
 │ ────────── BLE connect ──────────────▶ │
 │  ② 服务发现                             │
 │  ③ 读设备信息特征                        │
 │ ──── Read a004 ──────────────────────▶ │
 │ ◀─── "BTSH v0.1, ch=1" ─────────────── │
 │                                        │
 │  ④ 下发开灯                              │
 │ ──── Write a002: 01 02 01 01 ────────▶ │  继电器吸合
 │ ◀─── Notify a003: 82 03 01 01 00 ───── │  状态回报
 │                                        │
 │  ⑤ 心跳（每 30 s）                       │
 │ ◀─── Notify a005: 83 04 <uptime> ───── │
```

## 6. 异常处理约定

| 场景 | 行为 |
| --- | --- |
| A7Z 断连 | 灯**保持原状态**（不断电），RGB 转红色慢闪 |
| 重连成功 | 主动 Notify 一次当前全部通道状态 |
| 收到未知 OPCODE | 回 `ACK` with `0x01`，**不改变任何状态** |
| 报文 LEN 与实际不符 | 回 `ACK` with `0x02` |
| 心跳超时（>90 s 无连接） | 不自动关灯（安全策略待用户确认） |

> ⚠️ **待确认的安全策略**：断线后灯应该保持还是关闭？这取决于实际用途
> （照明 vs 警示）。默认选择「保持」，需用户拍板。
